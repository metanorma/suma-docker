== Purpose

This repository publishes a Docker container that adds EXPRESS schema tooling
(`eengine` and `eep`) on top of the
https://github.com/metanorma/metanorma-docker[metanorma-docker] image. SUMA
(STEP Unified Model-driven Architecture) ships with the `metanorma` gem and is
therefore already present in the base image; this repo installs no gems.

The container is published on GitHub Container Registry (GHCR) at
`ghcr.io/metanorma/suma-docker`.

== Supported platforms

[cols="1,1,1,2,3"]
|===
| Tag | OS | Architecture | Runner | Notes

| `latest`
| Linux
| amd64, arm64
| Any Docker host
| Multi-arch manifest. Default tag.

| `1.16.8`, `1.16`, `1`
| Linux
| amd64, arm64
| Any Docker host
| Versioned releases aligned with metanorma-docker (see <<_version_scheme>>).

| `windows`
| Windows
| amd64
| Windows Server 2022 or 2025
| Manifest pointing to `windows-ltsc2025`.

| `windows-ltsc2025`
| Windows
| amd64
| Windows Server 2025
| Requires Windows host with containers enabled.

| `windows-ltsc2022`
| Windows
| amd64
| Windows Server 2022
| Requires Windows host with containers enabled.
|===

NOTE: Linux containers work on any Docker host (Linux, macOS via Docker
Desktop, WSL2). Windows containers require a Windows host running in Windows
Containers mode.

On **Apple Silicon** (M1/M2/M3/M4) Macs, Docker Desktop pulls the `arm64`
variant automatically. On **Intel** Macs and most Linux servers, the `amd64`
variant is used.

The `arm64` Linux image runs eep (x86-64 only) via QEMU user-mode emulation.
This is transparent — no extra setup is needed.


== Quick start

Clone the https://github.com/metanorma/iso-10303[iso-10303] repository, then build a small test collection (parts 41–43):

[source,bash]
----
git clone https://github.com/metanorma/iso-10303.git
cd iso-10303

docker pull ghcr.io/metanorma/suma-docker:latest
docker run -it --rm -v $PWD:/metanorma ghcr.io/metanorma/suma-docker:latest \
  suma build metanorma-smol.yml
----

Output is written to `_site/` in the mounted directory. Open `_site/document.1.xml.0.html` to view the result.


== Included tools

The container provides the following commands, all available on `PATH`:

[cols="1,3,1"]
|===
| Command | Description | Source

| `suma`
| STEP Unified Model-driven Architecture — builds ISO 10303 collections, exports/compares EXPRESS schemas, validates links
| https://github.com/metanorma/metanorma[metanorma gem] (bundled in base image)

| `metanorma`
| Metanorma document compilation (AsciiDoc → XML/HTML/PDF)
| https://github.com/metanorma/metanorma[metanorma gem] (base image)

| `eengine`
| EXPRESS schema engine — used for schema comparison
| https://github.com/expresslang/eengine-releases[eengine] (installed by this image)

| `eep`
| Eurostep EXPRESS Parser
| https://github.com/expresslang/eep-releases[eep] (installed by this image)
|===


== Running the container

=== Build an ISO 10303 collection

The primary use case is building ISO 10303 document collections with
`suma build`. Mount the
https://github.com/metanorma/iso-10303[iso-10303] repository as `/metanorma`:

[source,bash]
----
docker run -it --rm -v $PWD:/metanorma ghcr.io/metanorma/suma-docker:latest \
  suma build metanorma.yml
----

The output appears in `_site/` inside the mounted directory.

Common site manifests in the iso-10303 repository:

[cols="2,4"]
|===
| Manifest | Description

| `metanorma.yml`
| Full collection

| `metanorma-srl.yml`
| STEP Resource Library (SRL)

| `metanorma-smrl-all.yml`
| Schema Model Reference Library (all)

| `metanorma-smol.yml`
| Small test collection (parts 41–43)

| `metanorma-single.yml`
| Single-part build (set `ROOT` variable)
|===

.Building without compilation:

`suma build` always compiles. To skip the slow document-compilation phase and only generate the schema manifest (useful for verifying that the collection parses and EXPRESS schemas process correctly), use `suma generate-schemas`:

[source,bash]
----
# Generate schema manifest only (no HTML/PDF output)
docker run -it --rm -v $PWD:/metanorma ghcr.io/metanorma/suma-docker:latest \
  suma generate-schemas metanorma-srl.yml schemas-srl.yml
----

For the full list of `suma` subcommands (`build`, `generate-schemas`, `export`, `compare`, `validate`, etc.), run `suma --help` inside the container.

=== Using the Makefile

The iso-10303 repository includes a Makefile with Docker support.
Append `docker` to any build target to run it inside the container:

[source,bash]
----
# Build a single part
make event docker

# Build the SRL
make srl docker

# Build with a specific image tag
make srl docker IMAGE=ghcr.io/metanorma/suma-docker:1.16.8
----

=== Export EXPRESS schemas

[source,bash]
----
# Export all schemas from a manifest
docker run -it --rm -v $PWD:/metanorma ghcr.io/metanorma/suma-docker:latest \
  suma export -o express-files schemas-srl.yml

# Export with annotations and ZIP archive
docker run -it --rm -v $PWD:/metanorma ghcr.io/metanorma/suma-docker:latest \
  suma export -o express-files --annotations --zip schemas-srl.yml
----

=== Compare schema versions

[source,bash]
----
docker run -it --rm -v $PWD:/metanorma ghcr.io/metanorma/suma-docker:latest \
  suma compare schemas/new/action_schema.exp schemas/old/action_schema.exp \
    --version 2
----

=== Validate EXPRESS cross-reference links

[source,bash]
----
docker run -it --rm -v $PWD:/metanorma ghcr.io/metanorma/suma-docker:latest \
  suma validate links schemas-srl.yml documents validation_results.txt
----

=== Generate schema manifest

[source,bash]
----
docker run -it --rm -v $PWD:/metanorma ghcr.io/metanorma/suma-docker:latest \
  suma generate-schemas metanorma-smrl-all.yml schemas-smrl-all.yml
----

=== Run other tools directly

[source,bash]
----
# Run eengine
docker run -it --rm -v $PWD:/metanorma ghcr.io/metanorma/suma-docker:latest \
  eengine --help

# Run eep
docker run -it --rm -v $PWD:/metanorma ghcr.io/metanorma/suma-docker:latest \
  eep -h

# Run metanorma directly
docker run -it --rm -v $PWD:/metanorma ghcr.io/metanorma/suma-docker:latest \
  metanorma document.adoc
----

=== Windows

NOTE: Windows containers require switching Docker Desktop to "Windows
Containers" mode (or running on a Windows Server with container support).

[source,powershell]
----
docker pull ghcr.io/metanorma/suma-docker:windows-ltsc2025
docker run -it --rm -v C:\iso-10303:C:\metanorma ghcr.io/metanorma/suma-docker:windows-ltsc2025 suma build metanorma.yml
----

For Windows Server 2022 hosts, use the `windows-ltsc2022` tag.


== Building the container locally

=== Linux

[source,bash]
----
docker build -t suma:latest .
----

=== Windows

[source,bash]
----
docker build -t suma:windows -f Dockerfile.windows .
----

To override the base image (e.g. to test against a specific metanorma version):

[source,bash]
----
docker build -t suma:test --build-arg BASE_IMAGE=metanorma/metanorma:windows-ltsc2022-1.16.8 -f Dockerfile.windows .
----


== Version scheme

This image's tags are aligned with the upstream
https://github.com/metanorma/metanorma-docker[metanorma-docker] version it is
built on top of, plus an optional suma-specific patch number:

[cols="1,4"]
|===
| Format | Meaning

| `X.Y.Z`
| First release built on top of metanorma-docker `X.Y.Z` (e.g. `1.16.8`).

| `X.Y.Z.N`
| N-th suma-specific patch on top of the same base image — e.g. an
  eengine bump or Dockerfile fix that doesn't change the metanorma base
  (e.g. `1.16.8.1`).
|===

The https://github.com/metanorma/suma-docker/pkgs/container/suma-docker[GHCR package page]
shows the available tags. The following tags always point at the newest version
meeting the constraint:

- `latest` — newest build on `main`
- `1` — newest `1.*`
- `1.16` — newest `1.16.*`
- `1.16.8` — newest `1.16.8` or `1.16.8.N`


== Identifying what's in a published image

Each published image carries OCI labels identifying the source commit and version. To inspect them:

[source,bash]
----
docker inspect --format '{{ index .Config.Labels "org.opencontainers.image.revision" }}' \
  ghcr.io/metanorma/suma-docker:latest
----

To dump every label:

[source,bash]
----
docker inspect --format '{{ range $k, $v := .Config.Labels }}{{$k}}={{$v}}{{"\n"}}{{ end }}' \
  ghcr.io/metanorma/suma-docker:latest
----

Each versioned tag (e.g. `v0.3.0`) also has a corresponding
https://github.com/metanorma/suma-docker/releases[GitHub Release] listing
the base image version, eengine version, source commit, and a compare link
against the previous release. Use this to answer "what changed in image SHA `abc123`?":

1. Look up the image digest on the GHCR package page or via `docker images --digests`.
2. Find the digest in the https://github.com/metanorma/suma-docker/pkgs/container/suma-docker/versions[package versions list]; each entry shows the source commit and pushed-at timestamp.
3. Match the commit to a https://github.com/metanorma/suma-docker/releases[release] (or browse the commit history directly).

based on, by platform.

|===
